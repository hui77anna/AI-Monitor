# 升级后切换无响应：版本恢复修复

系统日志显示组件时间线生成成功，但归档校验失败：`Bundle version did not match; LaunchServices DB may need to be rebuilt`。点击改变了选择，旧画面却无法被新时间线替换。

上游升级恢复逻辑把扩展标识写死为“主应用标识 + .widget”。AI Monitor 采用独立的 .aimonitor.widget 标识，因此跳过旧扩展进程清理，并记录该版本已尝试恢复。原位替换安装包后，旧进程可能继续运行而与磁盘上的新版不一致。

修复改为读取嵌入扩展的 Bundle ID，与签名标识严格一致并验证父应用前缀、签名有效性和团队。仍只清理同一签名要求、启动早于本次安装的旧扩展；不重置全系统数据库、不重启系统服务、不删除桌面组件或账户。

增加回归测试：上游标识、自定义标识均可验证，错签名及其他应用标识拒绝；保留旧进程/当前进程/其他应用进程的隔离测试。

## 验证

Build 187 → 188 原位升级，升级前保留运行中的扩展。新应用自动替换旧扩展进程，无手工清理系统服务。升级后 20 次、主程序重启后 10 次，合计 30 次左右切换全部通过。安装交接最初约 0.15 秒仍记录旧时间线版本错误，恢复后测试期间未再出现。4 项恢复逻辑测试及 make check 通过。
